# 双 RRF 的实测影响（截至 2026-10-26 现状）

> 复现脚本：[`analysis/rrf_slot_sim.py`](analysis/rrf_slot_sim.py)（可直接跑）、药品快照 `analysis/t_drug_dump.tsv`。
> 口径：精确复刻 `ChineseTokenizer` 分词 + `DrugRetriever` 打分 + `RrfFusion` 名次融合；KB 条数取自 `server/data/eval/latest.json` 里 2026-10-25 那次评测的 `hybridTop`；药品为 `t_drug` 中 `status=1` 且未删除的 **101** 条（表内共 126）。
> 局限：没有重跑向量检索，因此只知道每题的 **KB 条数**，不知道具体条目与 gold 名次。

---

## 一、三个可量化的影响

### 影响 1 · 事实题 40% 的上下文被药品占走

30 道 fact 题里，**27 道的 KB 证据被砍**（23 道各丢 2 条、4 道各丢 1 条、3 道不受影响），**合计 50 条知识库证据位被药品替换**。药品在这些题上平均占 **2.00 / 5** 个名额。

| 题目样例 | KB 召回 | 药品命中 | 最终 5 条证据的构成 |
|---|---|---|---|
| q01 高血压相关问题 | 5 | 3 | 3 KB + 2 药品 |
| q25 胃食管反流相关问题 | 2 | 3 | 2 KB + **3 药品**（药品占 60%） |
| q27 | 5 | 1 | 4 KB + 1 药品 |
| q58 汽车多久保养一次 | 0 | 3 | **0 KB + 3 药品** |

对照实验：若改成「KB 优先、药品只补空位」，KB 证据位损失 = **0 条**。

### 影响 2 · 拒答门控被药品放行（实测漏 1 题）

| 题 | 问题 | KB | 药品命中 | 线上实际行为 |
|---|---|---|---|---|
| q58 | 汽车多久保养一次比较合适？ | 0 | **3** | 进 LLM（本该拒答） |
| q53–q57、q59、q60 | 火星重力 / 比特币 / 珠峰 / 列表推导 / 世界杯 / 手机电池 / 地铁票价 | 0 | 0 | 正确拒答 |

`MedicalAgentService` 的拒答条件是 `evidence.isEmpty()`，而 `evidence` 是 **KB ∪ 药品** 融合后的结果。q58 的 KB 虽然为空，但药品返回了 3 条，于是**不拒答**，把 3 条药品证据拼进 prompt 让模型回答"汽车保养"。

评测记录的 `拒答率 1.0 (8/8)` 是按 `hybridRetriever` 单独判定的，**看不到药品这一路**。所以 README 的「拒答 8/8」在线上实际是 **7/8**。

**命中根因**：q58 被切成 `['汽车','车多','多久','久保','保养','养一','一次','次比','比较','较合','合适']`，其中 `一次` 命中 3 条药品描述里的"每周一次 / 每日一次 / 每周一次"。`一次` 在 101 条药品里 `df=3`，算出来的 IDF 是 **3.372**——**越罕见，分越高**，而"一次"恰恰是典型停用词。三条药分数完全相同（3.372），并列进榜。

### 影响 3 · 0.88 / 6.5 这两个阈值在最终名单上形同虚设

`HybridRetriever` 里标定的 `min-vector-score=0.88`、`min-bm25-score=6.5` 只决定"KB 这一路是否为空"。一旦进入第二层融合，`RrfFusion` 只看名次（`1/(K+rank+1)`），**从不读 `score()`**，所以：

- 一条 3.372 分的药品和一条 60 分的药品，拿到的名次分完全一样；
- KB 侧千辛万苦过完阈值的高分证据，被降格成"第 1 名 / 第 2 名"的记号，与药品平权。

## 二、哪些是"两次融合"造成的，哪些不是

这是本次实测最重要的结论——**不能把三件事都算在"双 RRF"头上**。

| 现象 | 是双 RRF 造成的吗 | 依据 |
|---|---|---|
| KB 名额被挤（27/30 题） | **部分是，但主因不是** | 模拟「只做一层 RRF，KB 15 条 + 药品 3 条」→ 结果同样是 **3 KB + 2 药品**。挤压的真正来源是 **RRF 对异构召回源做名次平权**：药品只要有命中，就必然按名次抢走约一半名额 |
| 0.88/6.5 门控失效 | **是，直接相关** | 第一层门控产出的分数被第二层丢弃；若只有一层，分数至少还留在 `Evidence.score` 里，后续可做分数兜底 |
| 第一层截断到 topK 后才参与融合 | **是** | KB 可贡献的名次被限制在 5 个，与药品的 3 个名次直接对撞 |
| 两套 K、两套去重 key 双维护 | **是** | `HybridRetriever:19` 与 `RrfFusion:14` 各有一个 `K=60` |
| q58 漏拒答 | **不是** | 药品非空即放行；即使只留一层融合，q58 仍是"KB 空 + 药品 3 条"，照样不拒答 |

**推论**：如果只按"把两次融合合并成一次"去改，**名额挤压和漏拒答都不会消失**。只删第二层、把药品 append 到 KB 后面，能救回名额（损失 0 条），但 q58 依然漏。三条都得改：

1. 药品侧加**分数阈值 + 停用词过滤**（否则"一次"这种词永远能进榜）；
2. 确定**融合策略**：KB 优先补位（保 KB 召回），还是给药品设**名额上限**（≤2）后再融合；
3. 拒答判定改成**只看 KB**（`retrieveKnowledge().isEmpty()`），药品命中不再单独决定"能否回答"。

## 四、对指标的影响（尚未验证）

`Recall@5 = 0.967` 是在 **KB 独占 5 个名额** 的口径下测出来的。线上实际只给 KB **3 个名额**，所以：

- 若某题的 gold 原本排在第 4、第 5 位，线上已经拿不到它——评测不会报错，因为评测不测合并后的名单；
- `MRR = 0.781` 说明确实有一部分 gold 不在第 1 名，因此"gold 落在被砍位置"的风险不是零，但具体几题需要重跑向量检索才能给出（本次未做）。

这条也说明：**评测与线上是两个不同的证据集**，`0.967` 不能当作线上质量的证明。

## 五、对回复质量的影响：不是"字数不够"，是"位置错配 + 引用错位"

### 5.1 先否掉一个直觉：字数是几乎没损失的

| 项 | 实测值 |
|---|---|
| KB 切片数 / 平均长度 / 中位 | 145 条 / **66 字** / **57 字**（最长 231） |
| 药品片段平均长度 | **53 字**（最长 68） |
| 典型事实题（3 KB + 2 药品）参考资料 | ≈ **306 字** |
| 改为 KB 优先（5 KB） | ≈ **332 字** |
| **正文净损失** | **8%（26 字）** |

切片按标题切分，演示语料小节密集，所以每个切片只有 57 字左右——**和药品片段（53 字）几乎一样长**。所以"药品抢走 40% 名额"在字符层面只造成 8% 的损失，**不是容量问题**。模型上下文 128k，这点差异无关痛痒。

### 5.2 真正的两个机制

**机制 A · 被挤掉的永远是 KB 的尾部证据**

`RrfFusion` 输出的顺序恒为 `KB#1, 药品#1, KB#2, 药品#2, KB#3`（同分按插入顺序，KB 先入）。也就是说：

- KB 的前 3 条**永远保留**；
- 被牺牲的总是**尾部**（KB 有 5 条时是 KB#4、#5；有 4 条时是 KB#4）；
- 药品证据不是排在末尾，而是**夹在指南中间**，占住了第 2、第 4 位这两个显眼位置。

由于切片很短（57 字），KB#4/#5 往往是一个**独立的小节**——比如某个具体数值、某条指征。因此被砍掉的可能正好是答案里那一个点。

**机制 B · 引用角标与证据对不上**

`SYSTEM_PROMPT` 要求"每条结论后必须附带引用角标"，且"不得引用范围外的编号"。融合后编号是 `[1]…[5]`，其中 `[2]`、`[4]` 指向药品说明书，`[1]`、`[3]`、`[5]` 指向指南。于是：

- 模型想说 KB#4 那条细节 → 该证据已不在上下文里，**要么不写，要么挂到药品角标上**；
- 医疗场景里"结论的证据不支撑结论"比"答得少"严重得多。

### 5.3 错配有多严重：14 道非药物 / 半药物题被塞进药品

按题目意图分，30 道 fact 题里 **16 道是药物题**（问具体药的剂量/禁忌/疗程），**12 道是明确的非药物题**（诊断标准 / 生活方式 / 评分工具 / 就医指征），另有 2 道介于两者之间。

在这 14 道非药物 / 半药物题上，药品证据至少是不回答所问，其中 6 道是**完全错配**：

| 题 | 问题 | 塞入的药品证据 |
|---|---|---|
| q11 | 糖化血红蛋白目标是多少 | 乳果糖口服溶液（便秘药） |
| q20 | CURB-65 评分包括哪些项目 | 硫酸氨基葡萄糖胶囊（关节） |
| q30 | 偏头痛预防常用哪些药物 | 蒙脱石散、碳酸钙D3片 |
| q17 | 普通感冒需要用抗生素吗 | 莫匹罗星软膏（外用）、维生素 B/C、双歧杆菌 |
| q19 | 上感体温超过多少天不退需就医 | 头孢呋辛酯、阿莫西林克拉维酸钾、头孢克洛 |
| q27 | HP 复查呼气试验前停 PPI 多久 | 双歧杆菌三联活菌胶囊 |

最典型的 q11：问"糖化血红蛋白目标"，上下文里塞了一条**乳果糖**——它进榜只因为描述里有"每日一次"之类的通用措辞。

### 5.4 结论

| 问题 | 回答 |
|---|---|
| 会挤占 40% 名额吗 | **会**，27/30 道事实题固定变成 3 KB + 2 药品 |
| 会因此"上下文不够用"吗 | **不会**，正文只少 26 字（8%），切片本身就短 |
| 会影响回复质量吗 | **会**，但通过两条别的路径：① KB#4/#5 被删，可能正好是答案那个具体数值；② 角标 `[2][4]` 指向药品，模型容易"结论挂错证据"或输出说明书口吻 |
| 哪类题受伤最重 | **非药物题**（诊断标准/评分/就医指征），12 道里 6 道被塞入完全无关的药品 |

**这条也给了个反直觉的推论**：修好名额分配（KB 优先）能救回 KB#4/#5，但**救不回被药品污染的语义**——只要药品参与融合且没有阈值，非药物题仍会拿到"话题相邻"的药片段。两个问题要分开修。

### 5.5 怎么真正测出"质量"差异（本次没做）

本次**没有**调用真实模型：环境无 `DEEPSEEK_API_KEY`，agent 会退化为 `MockLlmClient` 固定模板，答案质量无意义。要量化质量差异，需要：

1. 配一个 Key，同一 30 道 fact 题跑两遍（现状证据集 vs KB 优先证据集）；
2. 用可自动化的代理指标比对：**答案是否包含 gold 片段的关键数值/术语**（关键词命中率）、**引用角标是否指向支撑该结论的证据**（引用有效率）；
3. 两项都掉，才说明质量真的下降；只掉召回率而不掉答案，说明模型能从 3 条里补齐。
