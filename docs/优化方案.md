# aimin 整体优化方案

> 审计范围：`server/`（224 个 Java 文件）+ `admin-front/`（36 个文件）+ SQL/配置。
> 方法：3 个只读审计（后端 / 前端 / Agent 链路）+ 主会话自查，关键结论已抽查源码确认。
> 局限：未启动服务、未连 MySQL 实测；前端 build 被当前沙箱阻止（esbuild `spawn EPERM`）；离线 Maven 构建已实测通过。

## 一、结论

**当前是"能演示的 POC"，不是可上线的医疗辅助系统。** 三处硬伤任意一处都足以否定上线：

1. **鉴权三层全部失效**：网关对未登记路由默认放行（`/aimin-agent/**` 裸奔），admin 的注解拦截器被 `excludePathPatterns("/**")` 整体排除，服务端也没有第二道权限校验。
2. **Agent 三个 P0**：确认令牌不绑定问题、上传文件名可路径穿越、风险关键词大量漏判且只拦输入不拦输出。
3. **核心页面实际不可用**：知识库上传/列表 404，药品管理走 Feign 但无服务发现，验证码旁路仍在。

工程侧同时存在：0 个测试、server 不在 git、死模块（ai/search/canal）与重复模板、检索链路"有链路无质量"（中文自然语言药品召回几乎为 0）。
