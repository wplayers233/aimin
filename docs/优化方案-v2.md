# aimin 优化方案（奥卡姆版 · 2026-10-26）

> 本版**替换同文件上一版**（8 批 20 项）。上一版把"一个入口失守"拆成 6 个 P0 + 14 项工程债，是把实体乘得太多的写法。这一版只留必须做的那一件，其余进 backlog 并写明"什么时候才值得动"。
> 数据来源：[`双RRF影响实测.md`](双RRF影响实测.md)；`analysis/rrf_slot_sim.py` 可复算全部数字。

---

## 一、结论：只改一个类，两处逻辑

**给 `DrugRetriever` 补上和知识库侧同等的门控**（停用词 + 最低分），约 20 行 + 1 个配置项。

一个改动同时消掉三个"问题"：

| 原判定的问题 | 真实病因 | 改后 |
|---|---|---|
| q58 漏拒答（线上 7/8） | 药品零阈值，`一次` 让 3 条药进榜 | q58 命中 **0 条** → `evidence` 空 → 正常拒答 |
| 6 道非药物题被塞入完全错配药品 | 同上（`患者`/`药物`/`炎的` 等碎片） | 错配 **清零**（验收见 §四） |
| 27 题 KB 证据被砍、共 50 条位损失 | 垃圾药品占满名单 | 降到 **8 题 / 10 条**，且残留的都属"真药品题" |

**不做**：不动 `RrfFusion`、不动 `HybridRetriever`、不改拒答条件、不改 `refId`、不改评测器。

---

## 二、为什么不需要动融合层（推翻上一版）

上一版把"3 KB + 2 药品"归因到双 RRF，为此开了三个 P0。实测证明：

1. **RRF 没错**。它是名次融合，对异构源天然平权；单层融合同样是 3+2。挤压的真因是名单里混了垃圾。
2. **拒答逻辑也没错**。`evidence.isEmpty()` 是正确判据，错在喂进去的证据没门控。
3. **垃圾清掉后，药品挤掉一条 KB 是合理的**——那时它和 KB 同主题，不是噪声。

整条链路上没有一处"算法该换"，只有一个入口没设闸。

## 三、具体改什么

### 3.1 停用词（只作用于药品侧，**不动** `ChineseTokenizer`）

在 `DrugRetriever` 内对查询与药品文本做同一份过滤（`Bm25Index` 不受影响）：

```
一次 每日 每周 每月 每次 患者 病患 药物 服用 用于 常见 炎的 病的 者的
```

前 5 个是频次表述，中间 4 个是功能词，末 4 个是 bigram 跨词边界的碎片（`肺炎的` → `炎的`）。

### 3.2 最低分（`s >= minScore` 才入选）

配置项 `aimin.agent.drug.min-score`，本语料标定值 **12**。

| 参照点 | 分值 |
|---|---|
| 12 道药品题的 gold 最低分 | **13.35**（q35 双氯芬酸钠） |
| 去停用词后，6 道错配里最高的 | **5.84**（乳果糖在糖化血红蛋白题） |
| q58 垃圾分 | **0** |
| 边界样本 | q19 头孢呋辛 **11.98**——阈值取 11 会把它放进「多久不退需就医」题，取 12 刚好挡住 |

> 阈值是**语料相关**的：IDF 是在 101 条药品上算出来的。换库或扩库必须重标，所以做成配置项，不要写死。

## 四、验收（4 条，全部可自动比对）

```
□ q58「汽车多久保养一次」       → 药品 0 命中，返回 refused=true
□ 12 道药品题                  → gold 保留 12/12（当前 12/12，不许掉）
□ 非药物题上残留的药品证据       → 只剩 13 道真药品题（q07/08/12/13/16/18/21/22/23/24/25/26/28）
□ KB 证据位损失                 → ≤10 条（当前 50），被挤题数 ≤8（当前 27）
```

判定要点：**剩下 13 道题的药品证据，逐个看都必须是题目本身在问那个药**。出现一只"乳果糖在糖化血红蛋白题里"就算没过。

## 五、这一改不等于万事大吉：仍然存在的四件事

| 仍然存在 | 影响 | 为什么不顺手改 |
|---|---|---|
| 双份 RRF（两个 `K=60`、两套去重 key） | 行为上无害，纯重复；`架构说明.md` 4.4 与代码不符 | 跨 4 个文件 + 改 `refId` 语义（前端角标会变 `v1`）+ 动评测数字。收益是整洁，风险是改坏 |
| 药品相关题仍有 1–2 条 KB 位被占 | 被挤的 KB 与被塞的药品**同主题** | 属融合的正常行为，不是缺陷 |
| 阈值 12 只在这 101 条药品 / 60 题上标定 | 换库必重标 | 与既有 `0.88` / `6.5` 同性质，项目已按此运维 |
| 真实答案质量未测 | 无 `DEEPSEEK_API_KEY`，走 `MockLlmClient` | 需你给 Key；代理指标已定：gold 关键词命中率 + 引用有效率 |

## 六、Backlog：19 项工程债（明确"现在不做"）

它们不会让系统答错，只会让下次改动更疼。按**触发条件**排，而不是按优先级排：

| 什么时候值得动 | 事项 |
|---|---|
| 下次真动检索时 | 合并双 RRF、`Retriever` 接口、`Evidence` 补 `docId/chunkId`、评测口径分层 |
| 要接第二个 LLM 或大改 prompt 时 | 拆 `PromptAssembler` / `RiskGate`（待确认项换 Redis）/ `SseChannel` |
| 知识库要支持删除或多格式时 | 拆 `ChunkSplitter` + `KnowledgeIndexer`；清 registry 里的 `reg_upload_test.txt` |
| 会话量大到统计查询变慢时 | `AgentStatsRepository` 与 `AgentRepository` 拆分 |
| 有人要改权限模块时 | 统一 facade 边界、`PermissionTreeAssembler`、`deriveName` 去重 |
| 前端做第二轮体验优化时 | 401 收敛、`baseURL` 去重、`formatTime` 归位、`LineChart` 抽出 |
| 随时可做（零行为变化） | 内置 `ApiResponse` 替 9 处 `Map.of`、删 `VectorRetriever.docCount()`、线程池改 bean、修注释格式 |
| **需要你拍板** | `aimin-auth` 删 / 留待接入 / 标注占位（前端 0 调用，但先定微信登录是否在路线图） |
| **改完必做** | 同步 `README.md` 指标、`架构说明.md` 4.4、`regression.md` 口径 |

> "随时可做"那三项合计约 60 行、零行为变化。想清手感可以做，但**不要和 §三 混在同一个提交**，否则验收时说不清是谁的效果。

## 八、这次剃刀的教训

上一版 20 项 / 8 批 / 约 3 天，其中 **1 项是 bug、19 项是审美**。膨胀的原因是我把"代码里有重复"和"系统行为不对"混成了一张清单，又给每个观察都配了修法。

判据应当只有一条：**这个改动会让某道题的答案变对吗？** 会 → 做；只会让代码变整齐 → 进 backlog，等它真的挡住某次改动再说。
